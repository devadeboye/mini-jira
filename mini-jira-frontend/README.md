# Mini Jira Frontend - The Face of the Operation

This is the frontend application for my Mini Jira portfolio project, built with Next.js 15 and the App Router. It's where all the magic happens - the beautiful interface that makes project management feel effortless. I've focused on creating something that's both powerful and pleasant to use.

## What Powers This Beauty

- **Next.js 15** - Latest and greatest with App Router for smooth navigation
- **Tailwind CSS** - For that clean, modern look that doesn't get in your way
- **Zustand + React Query** - State management that just works, with real-time updates
- **NextAuth.js** - Secure authentication that handles all the heavy lifting
- **TypeScript** - Type safety that saves you from those 2am debugging sessions
- **Accessibility First** - WCAG 2.1 AA compliant because everyone deserves access

## Before You Start

Make sure you have these installed:
- Node.js 18 or newer
- pnpm (recommended) or npm
- The backend API running (check the backend README)

## Getting Everything Set Up

### 1. Install Dependencies
```bash
pnpm install
```

### 2. Environment Configuration
First, let's get your environment variables sorted:
```bash
cp .env.example .env.local
```

Your `.env.local` should look like this:
```env
# API Configuration
NEXT_PUBLIC_API_URL=http://localhost:4000

# Authentication (auto-generated by setup script)
NEXTAUTH_SECRET=your_generated_secret_here
NEXTAUTH_URL=http://localhost:3000
```

### 3. Auto-Setup (Recommended)
I've got a handy script that sets everything up for you:
```bash
pnpm run setup
```

This will create your `.env.local` file with a secure `NEXTAUTH_SECRET` and all the necessary configuration.

### 4. Start the Development Server
```bash
pnpm run dev
```

Your app will be running at `http://localhost:3000`

## Authentication Flow

I use NextAuth.js v5 with JWT tokens for authentication:

1. User logs in with credentials
2. Backend validates and returns JWT tokens
3. Frontend stores tokens securely in HTTP-only cookies
4. Automatic token refresh handles session management
5. Protected routes check authentication status

## State Management

I use a combination of Zustand and React Query:
- **Zustand** for UI state (modals, navigation, etc.)
- **React Query** for server state (projects, sprints, work items)
- **Local Storage** for user preferences

## Environment Variables

Here's what each environment variable does:

- `NEXT_PUBLIC_API_URL` - Backend API URL (must start with NEXT_PUBLIC_ for client access)
- `NEXTAUTH_SECRET` - Secret key for JWT signing (auto-generated)
- `NEXTAUTH_URL` - Your application URL (for auth callbacks)

## Deployment

### Building for Production
```bash
pnpm run build
```

### Deployment Checklist
1. Set production environment variables
2. Update `NEXTAUTH_URL` to your production domain
3. Ensure `NEXT_PUBLIC_API_URL` points to your production API
4. Run the build command
5. Deploy the generated `.next` folder

### Common Deployment Platforms
- **Vercel** - Easiest option, built by the Next.js team
- **Netlify** - Great for static exports
- **Railway** - Simple deployment with database support
- **AWS/Google Cloud** - For more control

## Troubleshooting

### Common Issues and Solutions

**Authentication not working?**
- Check that your `NEXTAUTH_SECRET` is set
- Verify the backend API is running
- Make sure `NEXT_PUBLIC_API_URL` is correct

**Styles not loading?**
- Run `pnpm run build` to regenerate Tailwind CSS
- Check for any CSS syntax errors

**API calls failing?**
- Verify the backend is running on the correct port
- Check CORS settings in the backend
- Ensure environment variables are set correctly

**Build failing?**
- Clear `.next` folder and rebuild
- Check for TypeScript errors
- Verify all dependencies are installed
